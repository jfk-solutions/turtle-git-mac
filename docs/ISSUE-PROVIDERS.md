# Issue tracker providers

TurtleGit's native issue provider lets Commit offer an issue-selection button,
update the commit message and issue ID, and check whether an issue is required.
The embedded **Native issue catalog** works locally. Windows COM providers cannot
run as native macOS providers; their UUID settings remain available for shared
repositories.

## Configure a working tree

Open Settings → Issue Tracker Integration and choose Add. Enable the association,
choose the exact working-tree folder, select Native issue catalog, then open
Options. The example is a starting point; replace its issues with your own IDs
and summaries. Confirm the editor, then Apply the settings. Cancel the editor or
settings page to discard its draft changes.

Associations match the exact working-tree folder, not all child repositories.
The first enabled matching association wins. Edit changes a row; Copy creates a
new row with its own identity; Remove changes the draft list until Apply.

The catalog parameters are JSON:

```json
{
  "linkText": "Choose issues…",
  "messageTemplate": "Issue: %BUGID%",
  "requireIssue": true,
  "issues": [
    { "id": "1", "summary": "Fix the import dialog" },
    { "id": "2", "summary": "Improve branch navigation" }
  ]
}
```

An empty messageTemplate updates only the issue ID. Otherwise, use one line
containing `%BUGID%`. Issue IDs must be unique and cannot contain commas or line
breaks. Commit's existing numeric-ID validation still applies: configure
`bugtraq.number = false` on Issue Tracker Config when using nonnumeric IDs.

## Use it in Commit

Open or Refresh Commit after applying settings. Its provider button uses your
linkText. Filter the issue list and select one or more rows; filtering preserves
selected issues that are temporarily hidden. OK uses catalog order and updates
the message and issue ID. Cancel preserves both fields. Choosing another issue
replaces the exact line previously generated by this provider.

With requireIssue enabled, Commit refuses to stage or commit without a known
catalog issue ID. The catalog provider makes no remote service writes. The
normal project issue-message rules, warnings and Git hooks still apply.

## Project fallback

When no enabled exact-path association matches, Issue Tracker Config can provide
`turtlegit.issueprovider` and `turtlegit.issueproviderparams`, using its existing
Local, Project or Global destinations. Set the provider ID to
`org.turtlegit.issue-catalog` and the parameters to the catalog JSON. These native
keys are separate from the Windows provider UUID and parameter fields.

An invalid or unavailable native provider reports a configuration error while
Commit's ordinary Git workflow remains available. Fix the association or fallback
and Refresh Commit. Third-party native providers, network-backed catalogs and
signed provider integration remain open work.
