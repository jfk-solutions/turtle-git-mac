## File/Open replacement ownership

`MergeEditorReplacementOwner.configureBeforeAdopt` applies launch policy to a prepared editor before detaching the accepted Open sheet, native window, or old controller. A thrown policy error closes only the prepared replacement. `onAdopt(next, previous)` publishes the new actual controller before its deferred first read; launch-session completion and Quit must follow that new owner. Replaced models remain retained while their cancelled reads/alignment/output work drains, exposed by `hasPendingRetiredWork`. The same receipt retains cancelled patch-preparation workflows until their actual loading task ends, even when their window's immediate `onFinished` callback has already run. `configurePatchWorkflow` installs patch readonly/reverse/label policy before preparation creates its embedded editor, so adoption never starts with an already-writable child.

Pinned `MainFrm.cpp::OnFileOpen` resets the explicit merged file and save-required flag. `WorkingFile.cpp::SetFileName` clears descriptive names but preserves reflected metadata; frame readonly/Blame and one-way state remain. `configureMergeToolReplacement` therefore carries immutable policy, current view mode and optional reflected metadata into a fresh comparison model. It does not reapply the original invocation's input paths, output, descriptive labels or line. The native launch protocol separately retains failure when the caller's originally requested result was discarded; ordinary replacement ownership does not erase that command obligation.
