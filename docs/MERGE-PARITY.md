# Merge dialog parity

The generic Merge prompt is replaced by a separate resizable native window.
Baseline: `7338078f8ddd924b8cddee35f512f2286072136d`, `MergeDlg.cpp`,
`MergeDlg.h`, `IDD_MERGE`, `CChooseVersion`, `MergeCommand.cpp` and
`AppUtils.cpp::DoMerge`. Compare with the
[upstream Merge manual](https://tortoisegit.org/docs/tortoisegit/tgit-dug-merge.html)
and [Git merge documentation](https://git-scm.com/docs/git-merge).

## Implemented

Current branch above From (Branch, Tag and Commit rows), followed by Option and
Merge Message groups, then OK/Cancel/Help. The current local branch is excluded
from the branch choices. A configured remote push branch is preferred when its
ref exists; detached HEAD is displayed explicitly. Branch browsing has a filtered
reference sheet; Commit browsing uses native Log in single-revision chooser mode.
The controller retains repository access and routes the chooser's existing
reference/checkout/Push actions to their native dialogs.

Squash disables the message editor and No Fast Forward. No Fast Forward disables
Squash and Fast Forward Only; Fast Forward Only disables No Fast Forward. No
Commit remains independent. Messages enables its count, initially positive
`merge.log` or 20. Strategy choices and recursive options match the pinned source.
Only recursive enables strategy options; rename-threshold/subtree enable the
parameter. Hidden option/parameter values are ignored as upstream does. The
message defaults to `<Auto Generated by Git>`, which sends no custom message.
Squash also ignores the disabled editor.

The actor invokes Git with literal argument arrays and validates the selected
commit, option combinations, count and strategy parameters before merging. It
uses the selected ref name for generated messages and `--no-edit` for unattended
message handling. It supports squash, no-commit, fast-forward flags, log summaries,
strategy/option/parameter and a custom multiline message. Failure retains Git's
conflict/recovery state and shows the error; open status/log/Commit windows and
the originating repository view are refreshed after success or failure.

## Verification

Five real-Git integration tests cover fast-forward preserving unrelated mixed
index/worktree edits, No Commit's fast-forward semantics, forced merge parents,
custom messages and summaries, pending MERGE_HEAD/message state, squash from an
annotated tag, validation before mutation, diverged fast-forward rejection,
conflicts remaining abortable, and different ours versus recursive/theirs results.
These tests establish the backend cases rather than full UI parity.

Native QA used `/private/tmp/TurtleGitMergeDialogQA`: Squash prevented editing;
Messages and fast-forward controls followed the upstream enablement. OK with
No Fast Forward, No Commit, Messages and a custom message preserved HEAD, set
MERGE_HEAD to the selected feature branch, staged its file and generated the
expected custom body and summary. Commit then loaded the pending message; enabling
staging mode and committing produced both expected parents, the feature file and
a clean index/worktree. The unrelated untracked file survived both operations.

A separate disposable layout fixture verified native Commit-chooser Cancel,
recursive strategy option enablement, rename-threshold parameter enablement,
Escape and Cancel. HEAD/index/worktree remained unchanged.
`site/assets/merge.png` is an actual 1360 × 1204 native capture of the final layout.

## Still partial

- Merge message history/context insertion, issue tracking, spelling/completion,
  editor font preferences and saved geometry.
- Full reference chooser controls, persisted revision history and native chooser
  acceptance with a different branch/commit, tag merge and detached/unborn cases.
- Progress output with cancellation and upstream post-operation actions: Resolve,
  Commit, Stash, retry unrelated histories, branch removal, Push and git-svn.
- Dedicated Abort Merge dialog and three-way conflict editor. Conflicts and abort
  are covered in backend tests; native conflict recovery is not yet verified.
- Interactive hooks/signing/editor workflows, strategy variants, user-data/rebase
  guards, dark/minimum-window/keyboard/sandbox runtime QA.

No complete Merge parity or App Store readiness is claimed. Completing pending
merges currently requires Commit staging mode; checked-file merge completion
remains an existing limitation.
