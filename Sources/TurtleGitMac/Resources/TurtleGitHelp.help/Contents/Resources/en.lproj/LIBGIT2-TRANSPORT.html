Optional libgit2 transport

TurtleGit includes an optional libgit2 engine for Clone, Fetch and the Fetch operations in Synchronization, including Fetch & Rebase and fetching a tag. The normal Clone/Fetch defaults remain Git commands, matching TortoiseGit's per-command defaults. SVN, ordinary Pull/Merge, Push, Prune and Remote Update continue through their existing command workflows.

The Advanced UseLibgit2 preference is the master switch. Like upstream, UseLibgit2_mask is a separate expert preference rather than an additional Advanced table row. Clone uses bit 0x2, Fetch uses bit 0x4; enabling both while retaining the source default mask means 0x66786 (decimal 419718). Disabling the master switch chooses Git commands regardless of the mask. A requested engine that is missing reports an error; it does not silently change the selected engine. The backend choice is captured when an operation starts, so editing Settings cannot change an operation already waiting for a folder, key or credential.

Both engines use the existing Clone/Fetch forms. Branch, origin, bare/no-checkout, recursive submodules, shallow depth, fetch destinations, tags, pruning and the pinned Rebase handoff retain their corresponding operation choices. Progress and cancellation remain owned by the window that started the operation. Fetch updates references and FETCH_HEAD; it does not itself merge, switch or overwrite working files. Follow-up Rebase/Merge remains a separate reviewed action.

An HTTP authentication challenge opens a native combined Username/Password dialog. This is libgit2's own credential callback. Git commands retain their existing credential-helper/askpass workflow. Password answers from this dialog are not written to progress output. The new callback does not save credentials or edit Keychain trust.

When the actual HTTPS connection presents an invalid certificate, Certificate verification failed! shows its hostname, issuer and fingerprints. Cancel is the default. Open certificate opens the native read-only inspector with public DER/PEM export. Accept certificate is temporary and exact to the actual host, port and certificate bytes in this operation; redirects to another authority cannot inherit it. Authentication and Git object transfer wait for the decision.

Cancelling an operation dismisses its owned authentication question. A certificate export already accepted finishes before the prompt releases its operation lock and before the transport process group is terminated. A late acceptance cannot restart a cancelled operation. Merely viewing or exporting a certificate does not accept it, install it in Keychain or change Git configuration.

SSH transport uses the bundled OpenSSH integration and its existing key/agent and host-key workflow. See SSH authentication and repository folder access. The source and validation record distinguishes implemented behavior from public-server, signed sandbox and complete upstream acceptance.

The optional engine does not currently run external Git filter/LFS process drivers or ordinary Git hooks. Repository template files are copied, but copying a hook is separate from executing it. Conventional custom GIT_ASKPASS programs and Git credential helpers are not consumed by this engine; use its native prompt or the default Git engine for those workflows. URL-specific HTTP headers, proxy and CA settings are resolved for the actual request URL, including redirects.
