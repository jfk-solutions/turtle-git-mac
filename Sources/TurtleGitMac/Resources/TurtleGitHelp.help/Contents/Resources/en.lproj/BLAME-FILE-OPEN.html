Blame File Open and recent files

See Blame menus and panes for annotation context menus, keyboard access, navigation and pane layout.

The pinned TortoiseGitBlameENG.rc File menu has Open, four recent files, Settings and Exit. TortoiseGitBlameDoc::OnOpenDocument reuses the SDI document, defaults subsequent Open to HEAD and adds only HEAD documents to MRU. Save/Save As strings are unused standard resources; there is no active Blame Save/Export menu to port.

The native File menu now offers Open, Recent Files, Settings and Close. Open uses an owned file sheet. A sandboxed file outside the current grant requests an owned repository-folder sheet before Git discovery. Cancel or failed permission/Git reads retain the current document, window and recent list. Preparing another document blocks ordinary close and is counted for Quit. Cancel waits for owned readers to settle before allowing another Open. Forced owner retirement cancels owned Git processes, fences picker replies and releases prepared replacement data.

Successful preparation captures a pinned HEAD blob, blame annotations and history before replacing the existing native window's content. Old source callbacks retire; an existing modeless Find panel/draft rebinds to the replacement. The new model starts at line one and binds context commands to the newly opened repository/access lease. The repository-model registry updates its identity, retaining any other existing window for the same file.

The private four-file archive contains a scoped bookmark, relative repository/file locations and a display path. It is atomically replaced with mode 0600. Only usable successful HEAD documents are registered; historical entrypoints do not add to MRU. A restored/moved scope is revalidated before reads, and successful reopening renews its bookmark and keeps its record ID. Unavailable/corrupt registrations report errors rather than permitting filesystem access or overwriting a corrupt archive.

Blame now reads the selected blob with rev-parse, literal NUL-delimited ls-tree and cat-file, avoiding a diff of the entire repository tree for a single source file. All blob/blame/history commands accept cancellation and retain exact source bytes. HEAD documents retain their requested HEAD identity for Reload; their snapshots remain pinned for displayed history. This keeps historical file reads and existing encodings while reducing work for large repositories. Read-only commands never modify HEAD, index or working files.

Zooming and reading a line's revision

Use View → Zoom In, Zoom Out or Actual Size in Blame. The shortcuts are Command-Plus, Command-Minus and Command-0. Command-Equals also zooms in. Command-wheel, Control-wheel and trackpad pinch work over source and attribution. Zoom changes both together, including wrapped rows, and keeps your selection and scroll location. It applies to the current document; Actual Size restores the font configured in Blame settings without changing that setting.

Hover a source line or its attribution to read its full revision, author/email, date and message preview. Different origin filenames are included when relevant. Long messages are bounded, and the preview follows the hovered line rather than the current selection. The source comparison records the implementation scope and remaining physical acceptance.

Symbolic-link files

Blame treats a versioned symbolic link as a Git file. Its source is the committed link-target text at the requested revision, including a target that is missing, a directory or outside the repository. It does not open that target. The usual HEAD default also means changing the link on disk does not change its displayed attribution until the committed revision changes.

File Open and Recent Files retain the link's own name. Their repository grant covers the selected entry's parent and Git metadata; no target-file grant is needed. A parent directory that redirects outside the granted repository remains unavailable. Gitlinks/submodules and directory trees are not Blame documents.

The same entry is supported by Repository Browser, Log's historical and working file actions, Finder/command-line routing and the existing source/history navigation. Follow-renames, previous-revision Blame and Reload retain the named Git path. A checkout with core.symlinks=false can still display the committed link blob even when its working file is a regular surrogate.

Reading the embedded Log

The Log pane shows the file's revision history. Colored labels identify local branches, remotes, tags and other references, using the same colors as the main Log. The current branch has its own color, annotated tags have a pointed label, and the repository's HEAD revision is bold. These values belong to the loaded history snapshot; Reload refreshes them after references change. Labels do not add unrelated commits to the file's history.

The Log font preference applies to this pane when LogFontForLogCtrl is enabled in Advanced settings. The font comes from the message-editor font settings. Rows grow with that font. This is independent of the source/annotation font and the source's temporary zoom. Multiline control characters use visible one-line substitutes in list captions; tooltips and Copy retain the original text.

Use the column header menu to show or hide metadata columns. Graph visibility follows the complete-log/follow-renames mode and cannot be changed independently in that menu. Message can be hidden. Column order, visibility and widths are saved for Blame separately from the main Log. Reset columns asks before restoring source defaults and fitting the current contents and headers. Fitting the Message column includes its reference labels.

When Diff by double-click in log is enabled, Return or a double-click compares the first selected revision with its first available parent. Multiple selection keeps the other selected revisions highlighted. Shift chooses the alternate comparison tool. Control-Return keeps its normal native handling. Parent menus retain their explicit parent choices and historical filenames.

Header actions and delayed comparisons retain their originating document and selection. Replacing or closing that document retires those actions rather than applying them to the newly opened file.
